# 个人知识库界面重设计

## 目标

把当前以“打开某篇文档”为中心的笔记界面，调整为以“浏览个人知识库”为中心的桌面应用。首次进入时展示知识库首页；首页、笔记、标签和设置拥有稳定入口；目录层级、当前文档和编辑/发表状态需要一眼可辨。

本次改造延续现有浅色、半透明、系统字体的视觉基础，不改变笔记内容格式、Tiptap 编辑能力、浏览器本地草稿机制或 GitHub Contents API 发布方式。

## 设计原则

- 导航稳定：主功能切换不能让整个应用框架消失。
- 层级明确：文件夹、文档、当前文档依靠图标、缩进、字重和选中面共同区分。
- 内容优先：阅读和编辑区域保持安静，工具只在需要时出现。
- 发表可预期：提交前说明会公开什么、会同步哪些索引；取消选择的变更继续作为本地草稿保存。
- 动效克制：反馈即时，过渡可打断，不使用装饰性弹跳。

## 整体布局

桌面端采用三段式应用框架：

1. 最左侧 56px 功能轨。
2. 约 260px 的上下文侧栏。
3. 占据剩余空间的主内容区。

功能轨依次提供：首页、笔记、标签、设置。底部保留回收站或用户标识。当前入口使用浅蓝选中面、蓝色图标和文字；悬停只增加轻微背景，不水平位移。

在首页、笔记和标签中，上下文侧栏显示“我的知识库”、搜索框和文档树。在设置中，上下文侧栏切换为设置分类。主框架不使用窗口红黄绿装饰点。

桌面宽度不足时依次折叠文档大纲、上下文侧栏和功能轨文字，不牺牲主内容可读性。窄屏以抽屉呈现目录，保留首页、笔记、标签三个核心入口。

## 文档树

文件夹行使用蓝色文件夹图标、展开箭头、600 字重标题和更大的组间距。文档行使用中性页面图标、常规字重标题并相对父文件夹缩进。计数和辅助操作仅作为次级信息。

当前文档同时使用：

- 整行浅蓝背景；
- 左侧 3px 蓝色指示条；
- 深蓝色标题；
- 当前文档的页面图标变蓝。

悬停状态不得强于选中状态。键盘焦点使用清晰的蓝色外描边。文档树保留现有拖拽、新建、重命名和删除能力。

## 知识库首页

应用默认视图为 `home`，首次进入不设置当前文档。页面标题为“知识库”，右上提供“新建笔记”。首页不展示最近编辑列表。

首页包含三个区域：

- 知识领域：根据文件夹或预设领域展示人工智能、工程实践、产品与设计、随手记录等入口，每项包含说明和文档数。
- 标签索引：展示常用标签及文档数，点击后切换到标签页并选中该标签。
- 库概览：展示文档、文件夹、标签三个总数。

默认启动行为写入设置：打开应用时为“知识库首页”，“记住上次打开的文档”默认关闭。若用户显式开启记忆功能，后续启动可恢复最近视图和文档。

## 标签页

点击功能轨中的“标签”只替换主内容，不离开应用框架，也不再进入知识网络画布。删除知识网络入口、全屏网络视图及对应背景效果；纯数据辅助模块可在无调用后移除。

标签页由以下区域组成：

- 标签搜索；
- 常用、名称、最近创建排序控件；
- 按技术、主题、工具、状态分组的标签列表；
- 当前标签详情和匹配笔记列表。

标签行统一字号，不使用词云。每行显示标签图标、名称和文档数。选中标签使用浅蓝背景和蓝色边框。点击匹配笔记时打开对应文档，并保持返回该标签筛选的上下文。

“新建标签”和标签重命名沿用现有标签数据模型；删除标签仍需遵守发表变更的依赖检查。

## 设置页

点击“设置”后，最左功能轨保持不变，上下文侧栏切换为以下分类：通用、外观、阅读与编辑、数据与同步、GitHub 发布、快捷键、关于。

首期需要真实生效并持久化的设置包括：

- 启动视图：知识库首页或上次位置；
- 主题：自动、浅色、深色；
- 侧栏密度：舒适、紧凑；
- 半透明材质：开、关；
- 正文宽度；
- 显示文档大纲；
- 默认进入阅读模式。

设置使用分组行布局：标签在左，控件在右，组间依靠留白和细分隔线。GitHub Token 不在概览页显示；现有仓库配置迁入“GitHub 发布”分类，敏感值只在编辑状态中输入。

## 阅读与编辑

选择文档后切换到笔记视图。顶部栏左侧显示文件夹与文档面包屑，中间显示自动保存状态，右侧依次为阅读/编辑切换、更多操作和“发表”。删除等低频或破坏性操作进入更多菜单，不与发表并列抢占注意力。

正文默认宽度约 720–780px，允许通过设置调整。标题下展示标签，文档大纲作为右侧可折叠辅助栏。大纲当前章节使用细蓝色指示条，不使用卡片。

编辑模式不显示永久的大型格式功能区：

- 选中文字时，在选区附近显示格式浮层；
- 当前块悬停时显示插入按钮和拖拽手柄；
- 表格、代码块和附件的专用工具继续靠近其作用对象；
- 所有编辑能力继续由现有 Tiptap/ProseMirror 实现。

自动保存反馈使用“保存中…”、“已自动保存”和失败状态，不通过持续动画吸引注意。

## 发表流程

点击“发表”后，在当前编辑页上打开居中的发表审阅浮层，而不是导航到独立页面。背景轻微变暗并后退，关闭后回到原编辑位置。

审阅浮层包含目标 GitHub 仓库、分支和连接状态，本次变更清单，会同步更新的目录和标签索引，公开标签及编辑入口，可展开的发布差异，以及未选变更继续保留为本地草稿的说明。

默认选中全部检测到的变更，并继续使用现有选择性发表模型。确认发表期间按钮展示进度并防止重复提交，但关闭入口和错误恢复保持可用。成功后关闭浮层，在编辑页显示轻量提示“已发表到 GitHub”；失败时保留选择与本地草稿，并在浮层内说明错误和重试方式。

## 视觉规范

- 字体：系统字体栈，包括 `-apple-system`、`BlinkMacSystemFont`、`SF Pro Text` 和 `PingFang SC`。
- 主文字接近 `#1d1d1f`；次级文字满足可读对比度。
- 系统蓝主要用于选中、链接、焦点和主要操作。
- 主内容面为暖白；功能轨和侧栏使用略深的半透明材质。
- 常规控件圆角 8–12px，浮层 18px；避免所有区域都卡片化。
- 优先使用留白和对齐，其次使用细分隔线，阴影只用于浮层。
- 图标统一使用同一套线性图标，不用文本符号模拟。

## 动效与无障碍

- 按下即时反馈，常规过渡约 160–240ms，使用无回弹或临界阻尼效果。
- 主区域切换使用短距离淡入，不让侧栏跟随重排跳动。
- 发表浮层从触发按钮的空间方向出现，关闭沿相反路径返回。
- 支持 `prefers-reduced-motion`、`prefers-reduced-transparency` 和更高对比度模式。
- 所有图标按钮提供可访问名称；功能轨、文档树、标签列表、设置导航和浮层支持键盘操作。
- 选中状态不能只依赖颜色，需要同时使用图标、指示条或文字变化。

## 状态与数据边界

应用状态增加明确的顶层视图：`home`、`library`、`tags`、`settings`。选择文档进入 `library`；选择标签进入 `tags`；设置页记录当前设置分类。`activeId` 可为空，不再被初始化逻辑强制替换为第一篇文档。

界面设置存储在独立的浏览器本地键中，避免与笔记草稿和已发布索引混合。已发布文档、目录和标签仍以 `notebooks/index.json` 为公开数据来源。

## 验证

自动化测试至少覆盖：

- 无本地偏好时启动到首页且没有当前文档；
- 开启“记住上次位置”后能恢复文档；
- 首页领域和标签入口切换到正确视图；
- 文件夹、文档和当前文档生成不同的语义与样式状态；
- 标签搜索、排序、选择和相关笔记过滤；
- 设置持久化及主题、密度、大纲和正文宽度的实际生效；
- 发表审阅继续正确调用现有选择性发表校验与合并逻辑；
- 未选变更与发表失败时的本地草稿保留；
- 小屏侧栏、键盘焦点和减少动效模式。

视觉验收使用与现有审查相同的桌面视口，对首页、标签、设置、编辑和发表审阅五个状态分别截图检查布局、溢出、对齐、文字层级与交互状态。

## 不在本次范围内

- 新建后端或更换 GitHub Pages 部署方式；
- 改变笔记 JSON 格式或迁移已有内容；
- 重新实现编辑器；
- 引入协作、账号、团队、计费、通知或 AI 功能；
- 保留知识网络作为隐藏入口；
- 为首页增加最近编辑、活动流、图表或推荐内容。
