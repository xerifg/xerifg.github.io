# 当前文档目录自动展开设计

## 目标

笔记目录默认保持收起状态，仅展开当前正在查看文档所在的文件夹及其所有父级文件夹。

## 方案选择

采用“派生默认折叠状态 + 手动折叠状态持久化”方案。

- 方案 A（采用）：在状态恢复时将所有文件夹标记为折叠，再从当前文档向上移除其祖先文件夹的折叠标记。目录模型继续只接收 `collapsedFolders`。
- 方案 B：渲染时根据当前文档动态覆盖折叠状态。会让用户收起当前路径的手动选择失效，不采用。
- 方案 C：新增独立的展开状态树。与现有 `collapsedFolders` 状态重复，范围过大，不采用。

## 交互规则

- 无当前文档时，全部文件夹默认收起。
- 有当前文档时，仅该文档父文件夹及其祖先文件夹展开。
- 用户仍可手动展开或收起任意文件夹；该选择按现有持久化机制保存。
- 选择另一篇文档时，自动确保新文档的目录路径可见，不强制收起用户手动展开的其它目录。
- 搜索时继续临时展示匹配项所需的目录路径。

## 实现边界与验证

- 在 `library-ui-model.mjs` 增加纯函数，计算默认折叠状态与文档目录路径。
- 在 `app.js` 的加载/选择流程中复用该函数，不修改目录渲染组件结构。
- 为纯函数增加测试：无活动文档、嵌套活动文档、手动展开保留三种情况。
