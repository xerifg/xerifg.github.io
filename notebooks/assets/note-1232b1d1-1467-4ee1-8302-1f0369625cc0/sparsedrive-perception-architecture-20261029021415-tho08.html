① 输入与共享特征提取

Input

多视角相机图像

通常为环视相机输入，例如 6 个视角。每个视角分别进入图像 Backbone。

I: [B, Ncam, 3, H, W]

Ncam 示例为 6；B 为 batch size。

Shared

Image Backbone

例如 ResNet-50，逐视角提取多层图像特征。

多层特征；通道数随 stage 变化

不是 Agent 与 Map 各自一套 Backbone。

Shared Neck

FPN

融合 Backbone 多个 stage 的语义信息，形成多尺度特征金字塔。

常见 embed_dims = 256

每个相机视角都有对应的多尺度特征。

Shared Feature Maps

多尺度 FPN 特征

以下是 4 层金字塔的典型表达；各层空间尺寸依赖输入分辨率和配置。

P2: [B,Ncam,256,H/4,W/4]
P3: [B,Ncam,256,H/8,W/8]
P4: [B,Ncam,256,H/16,W/16]
P5: [B,Ncam,256,H/32,W/32]

多视角图像输入

模型通常把每个相机的图像作为独立视角处理，并保留相机内外参用于把 3D 采样点投影到图像特征平面。相机数量、图像大小由数据与配置决定。

Backbone

负责从 RGB 图像中提取视觉特征。不同 stage 的特征具有不同空间分辨率和语义层次，后续 FPN 会把它们整合成统一通道数的金字塔特征。

FPN Neck

FPN 输出多尺度特征图。Sparse4D Decoder 的各层通常重复访问同一组 FPN 特征，而不是每层重新运行 Backbone/FPN。

多尺度维度怎么读

[B,Ncam,256,H/8,W/8] 表示 batch、相机数、通道数、高度、宽度。实际代码中可能把 B 与 Ncam 合并为一个维度，或将特征组织为 list/tuple。

两个 Head 的关系

两条分支共享图像 Backbone + FPN 的输出，但各自维护自己的 Anchor、Instance Feature、几何编码、Decoder 参数与细化模块。它们都使用 Sparse4D 风格的模块组合，但不是同一个 Decoder 实例，也不会在感知 Head 内简单地把 Agent Query 和 Map Query 拼到一起做同一组 Attention。

Anchor 与 Instance Feature 不是同一个东西

Anchor 是显式几何状态，例如中心位置、尺寸、朝向和速度；Instance Feature 是每个候选目标对应的高维可学习内容向量。它们一一对应并协同更新，但不应理解为把 Box 参数直接当成 256 维特征。

SparseBox3DEncoder

输入当前 3D Box 参数，编码成几何嵌入 anchor_embed。它可用于实例 Attention 的几何/位置编码，也会传入几何引导的特征聚合模块。它本身不从图像上采样，也不直接输出最终预测框。

注意：实际编码器可能对不同几何字段分别编码后再组合；“输出 256 维”是常见配置下的概括，具体中间分组维度以配置为准。

GNN / Attention

用于候选实例之间的交互。在 decouple_attn=True 的实现路径中，内容特征和几何编码分开处理后再组合进入注意力模块。常见配置的图模型输入维度为 512 = 256 + 256，但这不意味着每一层的 Q/K/V 都直接等于原始拼接向量，内部还会经过投影层。

时序 GNN（temp_gnn）是否存在于某一层，取决于 operation_order 与层配置；不要简单认为所有层完全相同。

3D Keypoint Generator

根据当前 Box 的位置、尺寸和朝向生成一组 3D 采样点，包括固定几何点和可学习点。点数、具体位置和坐标变换由实现及配置决定。

Deformable Feature Aggregation

采样点结合相机内外参投影到各个相机视图，然后从多尺度 FPN 特征图采样，并通过权重进行聚合。这里采样的是 FPN 特征向量，不是直接取 RGB 像素。每层通常重复读取同一组 FPN 特征，但由于 Anchor 更新，采样位置可以改变。

FFN / Norm / Residual

对实例特征做进一步非线性变换和稳定训练的归一化/残差更新。常见情况下，输入输出实例特征维度保持 [N,256]，方便层与层之间迭代。

SparseBox3DRefinementModule

根据当前实例特征预测 Box 参数的修正量、类别分数，以及配置支持的质量分数等。输出更新后的 Anchor 供下一层使用。它与 Encoder 的职责不同：Encoder 编码几何；Refinement 预测如何修正几何。

⑤ 最重要的架构理解

共享什么？

共享图像 Backbone + FPN 提取的多视角、多尺度图像特征。Decoder 的各层都可以从这组特征中取证。

独立什么？

Agent 与 Map 各自维护 Anchor、Instance Feature、几何编码、Decoder 参数和细化模块。结构相似，但不是同一个 Head 实例。

为什么要 Anchor + Feature？

Anchor 提供显式几何状态，Feature 提供可学习的语义/上下文表示。两者一一对应，联合迭代更新。

为什么每层都看图像？

每层根据当前几何状态重新生成采样点，从同一组 FPN 特征提取证据，逐步改善目标框或地图折线。

范围说明：本页面聚焦 SparseDrive 的 Sparse Perception。感知输出之后还会进入运动预测与规划相关模块；Agent 与 Map 在后续规划/预测阶段可能发生跨分支交互，这与感知 Head 内部是否共享 Decoder 是不同问题。
