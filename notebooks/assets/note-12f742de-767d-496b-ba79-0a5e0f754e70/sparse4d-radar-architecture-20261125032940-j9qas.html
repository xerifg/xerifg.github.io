Radar 点字段的代码级确认

配置使用 LoadRadarPointsMultiSweeps_omnihd，load_dim=8、sweeps_num=3、use_dim=[0..7]。VCS 代码明确取 points[i][:,:3] 作为邻域坐标，取 points[i][:,3:5] 作为 vx、vy。剩余通道参与 PillarFeatureNet，但其具体语义应以 OmniHD 数据定义为准。

输出 box 解码

内部 Anchor 使用 log 尺寸与 sin/cos yaw 表达；后处理将尺寸取 exp，将 yaw 通过 atan2(sin_yaw, cos_yaw) 还原。输出顺序可概括为 [x,y,z,w,l,h,yaw,vx,vy]。

04 · 关键机制演示

用交互小例子理解 Query 如何采样两种模态，以及 VCS 与 AMG 分别作用在哪个张量上。

机制 A · 同一个 3D Keypoint，映射到两种特征坐标系

Camera 路径：齐次投影矩阵将 3D Keypoint 投影到每个 Camera 的像素平面，再按 image_wh 归一化，转为 [-1,1] 的 grid_sample 坐标。

P_img = projection_mat · [x,y,z,1]ᵀ
u = X/Z；v = Y/Z
grid = 2 · (u,v)/image_wh − 1

Radar 路径：只使用 Keypoint 的 XY，按 point_cloud_range 归一化到 BEV 特征图坐标；Z 不参与 BEV 采样坐标。

x_norm = (x − x_min)/(x_max − x_min)
y_norm = (y − y_min)/(y_max − y_min)
grid_bev = 2 · (x_norm,y_norm) − 1

机制 B · VCS 速度一致性权重

VCS 不是对 BEV embedding 做相似度，而是：Anchor 的 vx,vy 与原始 Radar 点云中每个 Keypoint 半径 0.5m 内的邻域平均速度，分别经过共享 Velocity Encoder，再做逐通道点积、缩放、Sigmoid。所得权重逐 Keypoint 乘到已采样的 Radar BEV 特征上。

8.0 m/s
7.5 m/s
示意：速度较一致，VCS 会倾向保留该 Keypoint 的 Radar 特征。
E_k = VelocityEncoder(v_anchor)
E_r = VelocityEncoder(mean(v_radar_neighbors))
S = sigmoid(Σ(E_k ⊙ E_r) / √C)
S_refined = valid·S + (1−valid)·0.5
F_pts_new = S_refined · F_pts

滑块只展示机制，不模拟真实网络的 Encoder 参数或真实相似度数值。真实 S 必须由训练后的共享 MLP/LayerNorm 计算。

机制 C · AMG 自适应模态门控

先把 Camera 256 维和 Radar 384 维分别投影到 256 维，再拼接计算逐通道门控 G。

f_img = FC_img(F_img) → 256
f_pts = FC_pts(F_pts) → 256
G = sigmoid(FC([f_img; f_pts]))

门控不是简单给整幅图像或整个 Radar 一个标量；它是每个 Instance 的 256 维通道权重。

F_mix = G ⊙ f_img + (1−G) ⊙ f_pts
F_out = FC_out(F_mix) → 256

05 · 训练与推理路径

将共同的特征提取与 Head 路径分开看，避免把训练专用分支误认为推理主干。

训练 forward

  1. 读取多视角图像、三帧 Radar sweeps、标定与 GT。
  2. Camera：GridMask → ResNet/FPN；同时 DenseDepthNet 输出 3 个尺度深度图。
  3. Radar：Voxelization → PillarFeatureNet → Scatter → SECOND → SECONDFPN。
  4. Head 获取 900 learnable instances 与上一帧缓存；训练时构造 denoising anchors 并加 attention mask。
  5. 6 个 Decoder refinement stages 产生多层分类、box、quality 预测。
  6. 每层计算 Focal 分类损失与 SparseBox3D 回归损失；DN 分支单独计算辅助损失；另加 dense depth loss。

推理 forward

  1. Camera 与 Radar 双分支提取特征。
  2. InstanceBank 读取当前 900 anchors / features，并取有效历史缓存。
  3. Decoder 完成跨模态融合、时序交互和 Anchor 逐层 refinement。
  4. InstanceBank 缓存置信度 Top-K 的 600 个历史实例。
  5. SparseBox3DDecoder 对最终层分类分数做 Sigmoid、类别维 Top-K，解码 log 尺寸和 yaw。
  6. 返回 boxes_3d、scores_3d、labels_3d（可选 instance_ids）。

06 · 论文贡献、实现观察与工程问题

区分论文设计、代码可证事实和工程分析；不把推断包装成实验结论。

贡献 / 设计 1

目标 Query 驱动的 Camera–Radar Deformable Fusion。以 Anchor 生成 3D Keypoints，分别从 Camera PV 与 Radar BEV 采样，避免先构建稠密 Camera BEV 再融合。

贡献 / 设计 2

VCS（Acc）。利用原始 Radar 点云邻域速度一致性，对 Radar BEV 采样特征进行 Keypoint 级调制，意图抑制运动不一致的反射。

贡献 / 设计 3

AMG（Acc）。将两种模态映射到统一 256 维后逐通道门控，学习 Instance 级的模态贡献。

源码可确认的关键实现差异

  • Base：use_deformable_func=True，走自定义 DAF CUDA 聚合路径；没有 VCS / AMG 配置。
  • Acc：use_deformable_func=False，走 PyTorch grid_sample 路径，并在 Radar sampling 后插入 VCS，再用 AMG 融合。
  • VCS 插入点：features_pts = self.refine_layer(features_pts, key_points, anchor, metas['points'])，发生在 Radar BEV 多层级采样/加权之后、Keypoint 求和之前。
  • AMG 插入点：Camera 和 Radar 两支特征完成各自 Keypoint 聚合后，进入 fusion_layer(feat_img, feat_pts)。
  • Decoder 次序：配置表达式切片后，第 1 个 block 从 deformable 开始；后续 5 个 block 执行 temp_gnn → gnn → norm → deformable → ffn → norm → refine。

工程风险 / 研究问题

1. 标定误差直接影响跨模态采样。Camera Keypoint 投影依赖 projection_mat；Radar BEV 采样依赖 point_cloud_range 与坐标系一致性。外参偏差会使两个分支采样到不同物理位置。可做标定扰动鲁棒性测试、投影可视化与在线质量门控；论文架构本身不等于解决标定漂移。
2. VCS 依赖 Anchor 速度先验。Anchor 的 vx/vy 不准时，真实目标 Radar 特征可能被降权；邻域平均速度也可能被多径/邻近目标污染。建议分桶评估速度误差、有效邻域比例，并对 VCS 权重做可视化/消融。
3. 多帧累积与时间同步。Radar sweeps_num=3，历史实例另有 temporal cache。两种时间信息的坐标补偿/时间戳若不一致，可能造成运动拖影或 Anchor 对齐误差。
4. Acc 的算子路径与 Base 不同。Acc 关闭自定义 DAF，改用 PyTorch grid_sample，以支持 VCS 插入；性能差异不能简单归因于 VCS/AMG 本身。比较时要控制算子实现与输入配置。
5. 900 anchors / 13 keypoints 的效率权衡。稀疏不等于廉价；Camera sampling 的候选量约为 B×900×6×4×13，Decoder 还包含 900×900 的 Instance self-attention。需要结合实际 batch、特征尺寸与车载算力 profile。
